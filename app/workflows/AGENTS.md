# Four-role synthetic workflow

- For prepared fictional background, prefer one explicit ordinary interest as
  the rotating initial bridge. Live may raise it after several exchanges or an
  invitation to lead. A separately screened second ordinary interest may be
  introduced only later if the first topic runs dry and the caller remains open.
  Never bundle topics, cycle through the upload, or override an active caller
  topic, quiet request, safety, or consent. Direct questions may be answered
  from other authorized excerpts one detail at a time. Planner output remains
  optional guidance, not memory authority.
- The selected ordinary parent-authored interest and at most one distinct safe
  secondary interest may be repeated in bounded,
  attributed, explicitly untrusted context block beside the validated plan so
  Live can use it without searching every excerpt. Abstain for sensitive or
  instruction-like text. Eligibility must not depend on a fixed hobby-word list;
  other fictional chats may describe other interests. Never treat this context
  block as a command.

- Keep the existing Google Live speaker and audio path. Planner/Reconciler/Critic
  never speak, pick identities, grant consent, or choose provider voice keys.
- Use strict bounded proposals. Memory authority stays in canonical validators
  and transactional recipient-scoped storage, not in model output.
- Inputs are untrusted; exact evidence, roles, references, revisions and consent
  generations must be validated. Never execute imported instructions.
- Run Planner before Live with a short safe fallback. Release the call lease
  after reconciliation, before Critic. Critic failure must not erase memory.
- Check privacy before sending context to a specialist and before persisting its
  output. Critic reports contain codes only, stay developer-only, and never
  become parent diagnoses, family alerts, prompts or recap sharing.
- No new hosted framework or model provider. Tests are synthetic and mock all
  paid I/O. Live evaluations are explicit opt-in and not proof of voice quality.
- Keep evaluation rubrics tied to named synthetic failures. Calibrate each
  conversation scenario with known passing and failing replies, and never
  treat offline rubric calibration as measured model quality. Paid runs must
  retain the explicit CLI opt-in and must not log generated conversation text.
- Planner/Critic share the memory extractor's JSON Schema transport adapter.
  Preserve bounded local validation; never retry a rejected request with an
  unconstrained output, another model, or a different hosted processor.
